SCENARIO 2 - IDENTITY AND ACCOUNT COMPROMISE INVESTIGATION
============================================================

OKTA
----
Review:
- Successful authentication events
- Failed authentication events
- MFA challenges
- MFA approvals
- MFA denials
- MFA factor changes
- New device enrollment
- New session creation
- Session revocation
- Risk scores
- IP/network information
- User-agent/device information
- Administrative changes

QUESTIONS
---------
1. Was the DBA actually authenticated?
2. Which authentication factor was used?
3. Was MFA completed normally?
4. Was MFA reset shortly before the incident?
5. Was a new authenticator enrolled?
6. Was an existing session/token reused?
7. Were authentication events generated by the expected workstation?

CREDENTIALS
-----------
Review:
- Password changes
- API tokens
- SSH keys
- Certificates
- Service credentials
- Privileged credentials
- Credential exposure indicators

SSH / CERTIFICATES
------------------
Identify:
- Newly added keys
- Unexpected key fingerprints
- Recently modified authorized-key files
- Unknown certificate issuers
- Unexpected certificate changes

IMPOSSIBLE TRAVEL
-----------------
Treat geographic inconsistencies as anomaly indicators.

Validate against:
- VPN exit nodes
- Corporate proxies
- Cloud security gateways
- NAT
- Mobile networks
- Known DBA travel
- Time synchronization

Do not label impossible travel as confirmed compromise until the
network path and authentication evidence are correlated.

BREACH-CREDENTIAL CHECK
-----------------------
If organizational policy and legal authorization permit:
- Check whether relevant credentials appear in known breach datasets.
- Do not upload sensitive credentials to public services.
- Preserve evidence of any discovered exposure.
